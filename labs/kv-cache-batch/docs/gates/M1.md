# Gate M1：Batch Size 曲线

定位：这是已经关闭的 M1 **历史工作表**，保存 Batch Size Scan 的预测、执行与验收记录，不是当前实验任务书。当前 Gate 从[阶段 2 共学页](/learning/phase-2/)进入；原始数据与派生结果以 [`results/batch-size-scan/`](../../results/batch-size-scan) 为准。

状态：**Completed**

## Question

固定 `T=128` 时，Batch Size 从 `1` 增加到 `2/4/8`，Batched Decode 的整批延迟、摊销成本和输出位置吞吐如何变化？哪个点开始不再得到至少 10% 的相邻吞吐收益？

## 运行前预测

以下内容从实验开始时的 README 原样迁移到历史工作表，只移动存放位置，不按结果改写：

```text
H1：B 增大时，Batch Wall Time 会增加。
H2：Positions/s 会提高，但不会保持线性增长。
H3：Batch Wall Time / B 会下降，因为固定开销被摊薄。
H4：B=8 以内可能没有明确拐点；若没有，只能写 Not reached。
```

## Correctness Gate

- `B=1/2/4/8` 分别与独立 Sequential Oracle 数值等价。
- Batched Output、K Cache、V Cache 的 Shape 正确。
- Batch 内各 Sequence 的 Cache 状态互不污染。

## Measurement Contract

- 固定 `T=128`、`float64`、随机种子、权重和输入。
- 固定 `OPENBLAS_NUM_THREADS=1` 与 `OMP_NUM_THREADS=1`。
- 每个 Batch Size、每条路径保留 30 次原始测量，共 `4 × 2 × 30 = 240` 条。
- 汇总和曲线只从 [`raw.csv`](../../results/batch-size-scan/raw.csv) 重建，不手工录入结果。

## Result

|   B | Batch P50 / ms | Batch P95 / ms | P50/B / ms | Positions/s |
| --: | -------------: | -------------: | ---------: | ----------: |
|   1 |          1.442 |          1.467 |      1.442 |      88,750 |
|   2 |          1.789 |          1.808 |      0.894 |     143,129 |
|   4 |          2.627 |          2.673 |      0.657 |     194,928 |
|   8 |          5.264 |          5.312 |      0.658 |     194,513 |

相邻 Positions/s 增幅依次为 `61.27%`、`36.19%`、`-0.21%`。按“相邻增幅低于 10%”的事前定义，得到 **Knee = B=8**。

## Boundary and Next Decision

这里的 `P50/B` 是摊销执行成本，不是单请求延迟；Positions/s 也不是真实 Serving Token Throughput。这个固定 Shape 的 CPU/NumPy 实验不包含请求到达、排队、动态加入/退出、GPU Kernel、完整模型和网络。

因此不再继续扩大 B；M1 已关闭，下一项证据门禁是 M2 的 MHA/GQA Shape、正确性与 KV 容量。
