## 2. 从 C++ 切换到 Python 的最小心智模型

### 2.1 名称绑定，不是“变量里装着对象”

在 C++ 中，下面的赋值通常会调用拷贝语义：

```cpp
std::vector<int> a{1, 2};
auto b = a;
b.push_back(3);
// a 仍然是 {1, 2}
```

Python 的赋值默认只让新名称指向同一个对象：

```python
a = [1, 2]
b = a
b.append(3)

assert a == [1, 2, 3]
assert a is b
```

因此函数参数也不应该简单理解为 C++ 的“传值”或“传引用”。更准确的模型是：**调用时把对象引用绑定到函数内部的新名称上。**

```python
def append_sample(rows: list[float], value: float) -> None:
    rows.append(value)  # 修改调用者传入的同一个 list


samples = [1.0]
append_sample(samples, 2.0)
assert samples == [1.0, 2.0]
```

重新绑定局部名称不会替换调用者的对象：

```python
def replace_rows(rows: list[float]) -> None:
    rows = [99.0]  # 只让局部名称 rows 指向新对象


samples = [1.0]
replace_rows(samples)
assert samples == [1.0]
```

<SlideCard title="赋值、相等与身份">

## `=`

把名称绑定到对象；不承诺复制。

## `==`

比较两个对象的值是否相等。

## `is`

比较是否为同一个对象。最常见的正确用法是 `value is None`。

## 显式复制

- 容器浅复制：`items.copy()` 或 `list(items)`
- NumPy 数据复制：`array.copy()`
- 嵌套对象深复制：只在确实需要时使用 `copy.deepcopy`

</SlideCard>

### 2.2 可变对象与默认参数

Python 的默认参数在函数定义时求值一次，而不是每次调用时重新创建。

下面的函数会跨调用共享同一个列表：

```python
def bad_record(value: float, rows: list[float] = []) -> list[float]:
    rows.append(value)
    return rows


assert bad_record(1.0) == [1.0]
assert bad_record(2.0) == [1.0, 2.0]
```

应使用 `None` 表示“调用时创建”：

```python
def record(
    value: float,
    rows: list[float] | None = None,
) -> list[float]:
    if rows is None:
        rows = []
    rows.append(value)
    return rows
```

这也是阅读 Scheduler、Request State 或 Metrics 代码时必须敏感的地方：函数是否原地修改了传入对象？多个请求是否共享同一份容器？

### 2.3 `frozen=True` 不是深层不可变

当前 Benchmark 用 `@dataclass(frozen=True)` 表示一条计时样本：

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Sample:
    batch_size: int
    sequence_length: int
    elapsed_ms: float
```

它会阻止字段被重新赋值：

```python
sample = Sample(batch_size=2, sequence_length=128, elapsed_ms=1.5)
# sample.batch_size = 4  # FrozenInstanceError
```

但 `frozen=True` 只是浅层约束。如果字段本身是 `list` 或 `np.ndarray`，对象内部的数据仍可能被修改。它更接近“禁止给成员重新赋值”，不是 C++ 中可以递归推断的深层 `const`。

### 2.4 常用类型与 C++ 对照

| C++                         | 当前 Python 中的选择     | 需要注意的差别                           |
| --------------------------- | ------------------------ | ---------------------------------------- |
| `std::vector<T>`            | `list[T]`                | 可放不同对象；数值 Tensor 应使用 ndarray |
| `std::array<T, N>`          | `tuple[T, ...]`          | Tuple 不可重新修改，但元素可能是可变对象 |
| `std::unordered_map<K, V>`  | `dict[K, V]`             | 保留插入顺序；Key 必须可哈希             |
| `std::unordered_set<T>`     | `set[T]`                 | 无索引语义                               |
| `std::optional<T>`          | `T \| None`              | 使用 `is None` 判断                      |
| `struct`                    | `@dataclass`             | 类型注解默认不做运行时检查               |
| RAII Scope                  | `with` Context Manager   | 退出代码块时释放文件、锁或网络资源       |
| `std::span<T>`              | ndarray View             | View 共享 Buffer，所有权模型并不完全相同 |
| `std::chrono::steady_clock` | `time.perf_counter_ns()` | 适合测量时间间隔，不代表墙上时间         |
| `std::future` / Thread Pool | `asyncio.Task`           | Task 是协作式并发，不自动产生 CPU 并行   |

Python 内置 `int` 不是固定宽度整数；普通 `float` 通常对应双精度浮点数。进入 NumPy 后，`np.int64`、`np.float32`、`np.float64` 才重新具有明确的存储宽度。

## 3. 能维护当前实验所需的 Python 语法

### 3.1 直接遍历对象

不要把 C++ 下标循环机械翻译成 Python：

```python
batch_sizes = [1, 2, 4, 8]

for batch_size in batch_sizes:
    print(batch_size)

for sample_index, batch_size in enumerate(batch_sizes, start=1):
    print(sample_index, batch_size)
```

同时遍历多组数据使用 `zip`：

```python
batch_sizes = [1, 2, 4, 8]
wall_times_ms = [1.0, 1.7, 3.0, 5.5]

for batch_size, wall_time_ms in zip(batch_sizes, wall_times_ms, strict=True):
    print(batch_size, wall_time_ms)
```

`strict=True` 会在两个序列长度不同时抛出异常，适合实验数据对齐。

### 3.2 List、Generator 与一次性消费

List Comprehension 会立即创建完整列表：

```python
squared = [batch_size**2 for batch_size in (1, 2, 4, 8)]
assert squared == [1, 4, 16, 64]
```

Generator Expression 按需产生元素：

```python
rows.extend(
    Sample(
        batch_size=batch_size,
        sequence_length=128,
        elapsed_ms=elapsed_ms,
    )
    for elapsed_ms in samples
)
```

Generator 通常只能消费一次。需要重复遍历、求长度或随机访问时，应物化成 `list`；只需要向 `extend`、`sum` 或 `max` 连续供值时，可以保持惰性。

### 3.3 切片是左闭右开

Python 切片 `[start:stop:step]` 与 C++ Iterator Range 相似，`stop` 不包含在结果中：

```python
values = [10, 20, 30, 40]

assert values[:2] == [10, 20]
assert values[1:3] == [20, 30]
assert values[-1] == 40
assert values[::-1] == [40, 30, 20, 10]
```

但在 NumPy 中，切片除了选择范围，还会影响维度是否保留：

```python
# x: [B, T, D]
one_position_2d = x[:, t, :]          # [B, D]
one_position_3d = x[:, t : t + 1, :]  # [B, 1, D]
```

Attention 的 Batched Matmul 需要 `[B, 1, D]` 时，错误地写成 `x[:, t, :]` 可能让后续运算发生不符合预期的 Broadcasting。

### 3.4 解包、`*args` 与关键字参数

Python 可以直接解包返回值：

```python
output, weights, k_cache, v_cache = decode_step(...)
output, _, k_cache, v_cache = decode_step(...)
```

当前计时函数中的 `*args` 会收集额外位置参数：

```python
from collections.abc import Callable
from time import perf_counter_ns


def measure_once(fn: Callable[..., object], *args: object) -> int:
    start = perf_counter_ns()
    fn(*args)
    return perf_counter_ns() - start
```

函数定义中的单独 `*` 表示后续参数必须按名称传递：

```python
def record_sample(
    elapsed_ms: float,
    *,
    batch_size: int,
    sequence_length: int,
) -> Sample:
    return Sample(
        batch_size=batch_size,
        sequence_length=sequence_length,
        elapsed_ms=elapsed_ms,
    )
```

这样可以避免把多个相同类型的整数按错误顺序传入。

### 3.5 类型注解是静态契约，不是运行时护栏

```python
from collections.abc import Callable, Sequence

import numpy as np


def summarize(
    samples: Sequence[float],
    transform: Callable[[float], float] | None = None,
) -> tuple[float, float]:
    values = [transform(x) for x in samples] if transform else list(samples)
    return float(np.median(values)), float(np.percentile(values, 95))
```

这里需要能读懂：

- `Sequence[float]`：只要求可按序访问，不承诺是 `list`；
- `Callable[[float], float]`：接收一个 `float` 并返回 `float` 的函数；
- `T | None`：可能没有值；
- `tuple[float, float]`：返回两个浮点数。

Python 默认不会在运行时验证这些注解。当前 `pyproject.toml` 中的 Pyright 才负责静态检查；Shape、Dtype 与数值范围仍然需要运行时断言。

### 4.3 `pathlib` 与 `with`

```python
from pathlib import Path


def write_text(path: Path, content: str) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    with path.open("w", encoding="utf-8") as output:
        output.write(content)
```

`with` 是 Python 中最接近 RAII Scope 的结构。无论代码正常结束还是中途抛出异常，文件都会执行退出清理。文件、Lock、临时目录和 HTTP Stream 都应优先寻找 Context Manager 接口。

### 4.4 异常、`assert` 与测试

三者承担不同职责：

```python
def validate_batch_size(batch_size: int) -> None:
    if batch_size <= 0:
        raise ValueError("batch_size must be positive")


validate_batch_size(2)

# 程序内部不变量
assert k_cache.shape[:2] == (batch_size, sequence_length)

# 数值测试
np.testing.assert_allclose(expected, actual, rtol=1e-7, atol=1e-8)
```

- 非法用户输入：显式 `raise ValueError`；
- 内部逻辑不变量：`assert` 可以快速暴露实现错误；
- 长期回归保护：写入 `unittest`；
- 浮点结果：不要直接使用 `==`。

`assert` 可能在优化模式下被移除，因此不能承担外部输入验证或必须执行的业务逻辑。

## 5. NumPy：当前最重要的 Python 能力

### 5.1 把 ndarray 当成“Buffer + Metadata”

一个 ndarray 不只有 Shape。至少要同时检查：

```python
import numpy as np

rng = np.random.default_rng(42)
x = rng.normal(size=(2, 128, 64)).astype(np.float32)

assert x.shape == (2, 128, 64)
assert x.ndim == 3
assert x.dtype == np.float32
assert x.nbytes == 2 * 128 * 64 * 4

print(x.strides)
print(x.flags["C_CONTIGUOUS"])
```

<SlideCard title="每次 NumPy 运算前先问四件事">

## Shape

每个 Axis 分别表示 Batch、Head、Sequence 还是 Hidden Dimension？

## Dtype

一个元素占多少字节？运算是否发生隐式类型提升？

## Storage

当前对象拥有数据，还是共享另一个数组的 Buffer？

## Layout

Stride 是否连续？Transpose 后的访问模式会不会改变性能？

</SlideCard>

注意：`rng.normal` 默认产生 `float64`。如果实验要模拟模型常用的 `float32` 或更低精度，必须显式转换并记录；不能只在文章里写 dtype，却让代码继续使用默认值。

### 5.2 Axis 是张量语义的一部分

当前稳定 Softmax：

```python
def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    shifted = x - np.max(x, axis=axis, keepdims=True)
    exp_x = np.exp(shifted)
    return exp_x / np.sum(exp_x, axis=axis, keepdims=True)
```

假设 `scores.shape == [B, 1, T]`：

- `axis=-1` 表示沿历史 token 归一化；
- `keepdims=True` 让最大值保持 `[B, 1, 1]`；
- `[B, 1, T] - [B, 1, 1]` 通过 Broadcasting 完成；
- 如果误写 `axis=0`，程序仍可能运行，却会让不同 Sequence 互相归一化。

因此 Shape 测试不只是防止 Crash，还要防止**合法 Shape 上的错误语义**。

### 5.3 Broadcasting 从最右边的维度开始

两个维度满足下列任一条件即可兼容：

1. 两者相等；
2. 其中一个为 1。

例如：

```text
scores:  [B, 1, T]
max:     [B, 1, 1]
result:  [B, 1, T]
```

Broadcasting 通常不会真的复制较小数组，但它也可能产生巨大的中间结果。写代码时不能只问“能不能 Broadcast”，还要问“Broadcast 以后结果 Shape 和内存量是什么”。

### 5.4 `@` 对最后两个维度做矩阵乘法

当前 Batched Attention：

```python
# q_t:     [B, 1, D_k]
# k_cache: [B, T, D_k]

k_t = np.swapaxes(k_cache, -1, -2)  # [B, D_k, T]
scores = q_t @ k_t                  # [B, 1, T]
```

`@` 把最后两个维度当作矩阵维，前面的维度作为 Batch 维处理。这里每个 `q_t[b]` 只与同一个 `b` 下的 K/V 相乘，所以 Sequence 之间不会发生 Attention。

必须用不同 Sequence 数据的 Oracle 来验证这一点。仅检查输出 Shape `[B, 1, T]`，无法证明 Batch 间没有状态泄漏。

### 5.5 View、Copy 与 Benchmark 假象

基础切片通常产生 View：

```python
x = np.arange(8)
view = x[2:5]
view[0] = 99

assert x[2] == 99
assert np.shares_memory(x, view)
```

Advanced Indexing 通常产生 Copy：

```python
x = np.arange(8)
copied = x[[2, 3, 4]]
copied[0] = 99

assert x[2] == 2
assert not np.shares_memory(x, copied)
```

当前实验里的几个操作具有不同成本：

| 操作                           | 常见行为         | 对实验的影响                  |
| ------------------------------ | ---------------- | ----------------------------- |
| `x[:, t:t+1, :]`               | View             | 通常不复制 Tensor 数据        |
| `np.swapaxes(x, -1, -2)`       | View             | 改变 Stride，不保证连续       |
| `np.concatenate([cache, new])` | 分配新数组并复制 | 每个 Decode Step 累积分配成本 |
| `np.stack(sequences, axis=0)`  | 创建新数组       | 构造 Batch 的成本不应混入计时 |
| `np.empty(shape, dtype)`       | 分配但不初始化   | 写入前读取会得到未定义内容    |
| `array.copy()`                 | 显式复制数据     | 需要隔离状态时使用            |

这正是 Dynamic Cache 与 Preallocated Cache 的区别：前者每一步都通过 `concatenate` 重新分配并复制，后者只在开始时分配一次，然后写入有效 Slice。

<Note title="C++ 使用者最容易犯的 NumPy 错误" class="title-underline">

不要把 ndarray Slice 当成独立的 `std::vector`。修改 Slice 可能直接修改原始数组；Transpose/Swapaxes 可能只改变 Metadata；`reshape` 有时是 View、有时需要 Copy。需要隔离状态时显式 `.copy()`，需要验证时使用 `np.shares_memory`、`.base`、`.strides` 与 Contiguous Flag。

</Note>

### 5.6 随机数与数值正确性

使用独立 Generator：

```python
rng = np.random.default_rng(42)
x = rng.normal(size=(2, 128, 64))
```

固定 Seed 只能保证**相同版本和相同调用顺序下的随机流可重复**。如果在循环中新增一次 `rng.normal`，后面的所有输入都会变化。公平对照时，应先构造一次输入和权重，再让不同路径共享它们。

浮点路径使用：

```python
np.testing.assert_allclose(
    expected,
    actual,
    rtol=1e-7,
    atol=1e-8,
)
```

必须根据 Dtype 与累计运算误差选择容差。不能为了让测试通过而不断放大 `atol`；若误差随 T 或 Head 数增长，应先检查数值稳定性和 Shape 语义。

## 6. 用 Python 写可信的性能实验

### 6.1 计时范围必须足够小且明确

```python
from collections.abc import Callable
from time import perf_counter_ns


def measure(
    fn: Callable[..., object],
    *args: object,
    warmup: int = 3,
    repeats: int = 30,
) -> list[float]:
    for _ in range(warmup):
        fn(*args)

    samples_ms = []
    for _ in range(repeats):
        start = perf_counter_ns()
        fn(*args)
        elapsed_ms = (perf_counter_ns() - start) / 1_000_000
        samples_ms.append(elapsed_ms)

    return samples_ms
```

这个函数适合当前 Microbenchmark，但仍要明确：

- 它测量 Wall Time，不是纯 CPU Cycle；
- Python 调用、数组分配、NumPy Dispatch 与底层 BLAS 都包含在内；
- 输入和权重应在计时区间外创建；

## 7. 后续 Serving Harness 所需的 `asyncio`

### 7.1 Async 是等待期间让出执行权

`asyncio` 适合大量等待网络响应的任务。它默认运行在单个 Event Loop Thread 中，通过 `await` 协作切换；这不是自动的多核并行。

```python
import asyncio
from time import perf_counter_ns


async def simulated_request(
    request_id: int,
    gate: asyncio.Semaphore,
) -> tuple[int, float, float]:
    arrival_ns = perf_counter_ns()

    async with gate:
        admitted_ns = perf_counter_ns()
        await asyncio.sleep(0.01)
        finished_ns = perf_counter_ns()

    queue_ms = (admitted_ns - arrival_ns) / 1_000_000
    e2e_ms = (finished_ns - arrival_ns) / 1_000_000
    return request_id, queue_ms, e2e_ms


async def main() -> None:
    gate = asyncio.Semaphore(4)
    tasks = [
        asyncio.create_task(simulated_request(request_id, gate))
        for request_id in range(16)
    ]
    results = await asyncio.gather(*tasks)
    print(results)


if __name__ == "__main__":
    asyncio.run(main())
```

这里要区分：

- 创建了 16 个未完成 Task；
- Semaphore 只允许 4 个进入受控区间；
- 这表示 Client Concurrency 上限为 4；
- 服务端每个 Engine Step 的实际 Sequence Batch 仍由 Scheduler 决定。

### 7.2 流式请求需要记录四类时间

后续 HTTP Client 至少保存：

```text
arrival_ns      client creates request
sent_ns         request is admitted and sent
first_token_ns  first streamed token arrives
token_times_ns  every following token timestamp
finish_ns       stream finishes or fails
```

从这些时间才能计算：

- Client Queue Time；
- TTFT；
- 每个 ITL；
- TPOT；
- E2E。

不要在 Coroutine 中调用 `time.sleep()`，它会阻塞整个 Event Loop；需要等待时使用 `await asyncio.sleep()`。不要让多个 Task 无保护地修改同一份结果对象；最简单的做法是让每个 Task 返回独立结果，再由调用方汇总。

## 8. 阅读 vLLM Python 源码需要识别什么？

进入源码前，不需要先掌握所有 Python 魔法。先能识别下面的结构：

| 看到的结构                  | 阅读方式                                   |
| --------------------------- | ------------------------------------------ |
| `@dataclass`                | 先找状态字段、默认值与可变字段             |
| `Enum`                      | 画出 Request Status 的合法状态集合         |
| `Protocol` / `ABC`          | 区分接口契约与具体 Backend 实现            |
| `T \| None`                 | 找出状态缺失的合法时机                     |
| `list[Request]` / `dict`    | 判断谁拥有容器、谁会原地修改               |
| `async def` / `await`       | 找出可能挂起和恢复的位置                   |
| `with` / `async with`       | 找出资源生命周期边界                       |
| `yield` / `async for`       | 把函数看成逐步产生结果的 Iterator / Stream |
| `@property`                 | 读取时可能执行逻辑，不一定只是字段访问     |
| `raise` / `try` / `finally` | 追踪失败、取消和资源释放路径               |

源码纵切时，优先追踪 Request State、Scheduler Budget、KV Block 生命周期和 Model Runner 调用链。遇到陌生装饰器或泛型语法时按需补齐，不要暂停主线去完整学习 Python Data Model。
